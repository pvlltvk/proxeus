**Cross-group dedup now works against real Thanos and VictoriaMetrics stacks, and can fill one backend's gaps from
another.** Until now, two stacks scraping the same target almost never produced matching series, because each backend
stamps labels of its own, so dedup passed both copies through and joins failed. And when copies did match, a hole in
the winning copy stayed a hole even when the other backend had the data. Both are fixed behind new options; **with
default config, query results are the same as v0.3.3.** One metric changes meaning, see below.

## Cross-group dedup

**`cross_group_dedup_ignore_labels`** (#43). Dedup identifies a series by its labels minus each group's `labels` keys.
Labels a backend adds by itself, such as Thanos Receive's `receive_replica` and `tenant_id`, kept copies of the same
series apart. List them here and they no longer count toward identity; they are still returned on the winning series.

```yaml
proxeus:
  cross_group_dedup: true
  cross_group_dedup_ignore_labels: [receive_replica, tenant_id]
```

Against the sandbox (Thanos Receive and VictoriaMetrics, both scraping `node-exporter` and `avalanche-shared`):
one-to-one joins such as `rate(x[5m]) / on(instance, cpu, mode) rate(x[5m])` used to fail with 422 "many-to-many
matching not allowed" over 1h, 6h and 48h ranges, and now answer. `up` returns 24 series instead of 26, and
`/api/v1/series` for `node_uname_info` 3 instead of 4. With `cross_group_exact_aggregates: true`, `count(up)` is 24
instead of 26. A longer ignore list adds no allocations; where copies now collapse, dedup allocates less (3.78 MB →
1.72 MB per 10,000 series in the benchmark), because the losers' samples are never read.

Don't list labels that tell genuinely different series apart, such as `instance` or `job`. That would merge them.

**`cross_group_dedup_fill_gaps`** (#44, off by default). The dedup winner (the lowest-ordinal group) used to be
returned whole, so a hole in it stayed a hole. This is common in a migration: the new backend lacks history, or the
old one stops first. With the option on, the winner keeps every sample it has and the other groups fill only its
gaps, in ordinal order. A gap is the span before the winner's first sample or after its last, an interval at least
`cross_group_dedup_gap` long (default: twice the winner's median sample interval), or the span after a staleness
marker.

```yaml
proxeus:
  cross_group_dedup: true
  cross_group_dedup_fill_gaps: true
  cross_group_dedup_gap: 0   # 0 = auto
```

In the sandbox, with an 8-minute scrape outage on each stack at different times, a 30s-step range query over 24
minutes:

| Query | VM first, on | VM first, off | Thanos first, on | Thanos first, off |
|---|---|---|---|---|
| `up{job="node-exporter"}` | 46 points, no gap | 30, gap | 46, no gap | 40, gap |
| `rate(node_cpu_seconds_total[1m])` | 46, no gap | 32, gap | 46, no gap | 30, gap |

Values can differ slightly where a filled stretch meets the winner's own data (downsampled Thanos next to raw
VictoriaMetrics, or scrapes at different moments), as with Thanos Query's own replica dedup. Pushed-down aggregations
are not deduplicated, so they are not filled; with `cross_group_exact_aggregates: true` they are.

**It is off by default because it costs memory.** Every series present in more than one group has all its copies
read. In the benchmark (3 groups × 2000 series, no gaps), 5% overlap goes from 1.85 MB to 3.30 MB per query and 50%
overlap from 1.44 MB to 14.6 MB. During a migration most series overlap, so measure it on your dashboards before
turning it on. We plan to make it the default after a longer soak.

## Metrics

**`proxeus_pushdown_nodes_total{node="subquery"}` no longer reports `pushed` for a subquery with nothing pushed
inside it** (#42). It counted every subquery as pushed; `(vector(1))[10m:1m]` counted `subquery/pushed` with zero
downstream requests. Such subqueries now record `fallback` with `reason="no_inner_pushdown"`. Queries and downstream
requests are unchanged; dashboards or alerts on the subquery pushdown ratio will see it drop to its real value.

template changes.

## Upgrade notes

No config changes are required, and both new options are opt-in. `cross_group_dedup_ignore_labels`,
`cross_group_dedup_fill_gaps` and `cross_group_dedup_gap` all require `cross_group_dedup: true` (and the gap option
requires fill gaps), and a config that sets them without it is rejected at load and by `--check-config`.
