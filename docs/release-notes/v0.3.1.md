Patch release. Two things: the config checker now catches a case it used to pass, and the image no longer ships a
known-critical Go stdlib.

## Security

**The published image was built on Go 1.25.5, which carries `CVE-2025-68121`** (critical, fixed in 1.25.7). The cause was
a base-image pin, not a missed upstream release: `golang:1.25-alpine3.21` has no builds past 1.25.5 — later patches ship
`alpine3.22`/`3.23`/`3.24` instead — so the tag silently stopped receiving Go security updates. CI's `setup-go` tracks the
latest 1.25 patch, so proxeus was being tested on a patched Go and shipped on an unpatched one. The Dockerfile now uses
`golang:1.25-alpine`; the v0.3.1 image is built on **Go 1.25.14** (#33).

Dependencies with open advisories were bumped to the highest versions that still declare Go 1.25 — `x/crypto` to v0.55.0,
`x/net` to v0.58.0, `x/text` to v0.41.0, `grpc` to v1.84.0. `x/crypto@latest` and `x/net@latest` now require Go 1.26, and
adopting them would have forced a toolchain migration across the Dockerfile and CI, which does not belong in a patch
release; `go.mod` still declares `go 1.25.0`. `github.com/docker/docker` is unchanged — its findings have no fixed version
published.

## Fixes

**`--check-config` now rejects a config that startup refuses** (#32). Two `server_groups` sharing the same `labels` with
`cross_group_dedup: true` is fatal at startup, but `--check-config` exited 0 on it, because the label-collision pre-flight
lived in `ProxyStorage.ApplyConfig` — a stage `--check-config` never reaches. It now runs at config load, so
`--check-config`, a SIGHUP reload and startup all reject the same configs. This matters for the Helm chart, which runs
`--check-config` in an init container: a config that passed preflight could still crash-loop the pod.

Unchanged deliberately: without `cross_group_dedup` a label collision remains a warning and the process starts, since
there it is only a provenance concern. Only the dedup case is fatal. Configs rejected at load now report
`error loading cfg: server_group label collision: …` rather than `failed to apply configuration: …`.
