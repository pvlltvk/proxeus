**Fixes from a code review: an authentication bypass, a native histogram memory leak, and downstream `http_client`
options that were accepted but ignored.**

## Security

- **CORS preflights no longer bypass authentication** (#50). The auth middleware lets CORS preflights through
  unauthenticated, and `/api/v1/status/config`, `/api/v1/metadata`, `/api/v1/status/walreplay` and
  `/api/v1/status/flags` answered them like a GET: an `OPTIONS` request with `Access-Control-Request-Method: GET`
  returned the configuration YAML without credentials. Secret fields were redacted, but topology and plain
  `http_headers` values were not. These routes are now GET-only, as in upstream Prometheus, and every unrouted
  `OPTIONS` request is answered by the upstream CORS handler without reading any data.

## Correctness

- **Native histogram memory leak** (#52). Every native histogram converted on the remote_read and merge paths stayed
  in memory for the life of the process; the cleanup that was meant to release it could never run. Entries are now
  released once the query result is.
- **`offset` on native histograms** (#50). When a pushed-down selector turned out to return histograms and proxeus
  fell back to raw evaluation, the selector's offset stayed removed: `foo offset 1m` returned the samples at the query
  time instead of one minute earlier.
- **Time filters** (#50). A relative `end` truncated requests in the wrong direction (a request ending before the
  configured bound was extended to it, one ending after it was not capped), and an absolute filter with no `end`
  sent label-name requests with an end in year 1.
- **Reloads** (#50). Removing a server group, or reloading the config, now stops that group's label-filter pollers;
  previously they kept querying the old backends.

## Downstream `http_client`

Every option of a server group's `http_client` is now either applied to the query transport or rejected at config
load. Remote read already used the full Prometheus client and was not affected.

- **Now applied** (#50, #51): `authorization` (with `credentials` or `credentials_file`; type defaults to `Bearer`),
  `follow_redirects`, `enable_http2`, `no_proxy`, `proxy_from_environment`, `proxy_connect_header`, `http_headers`
  and `basic_auth.username_file`. A header set in the group's own `http_headers` wins over the same header in
  `http_client.http_headers`.
- **Defaults changed**: `follow_redirects` and `enable_http2` now default to `true`, as in Prometheus, so HTTPS
  backends are reached over HTTP/2.
- **Rejected at load**: `oauth2`, `authorization.credentials_ref`, the `basic_auth` and TLS `*_ref` secrets, both
  `username` and `username_file` (or `password` and `password_file`) set at once, and invalid proxy or header options.

## Tests

A differential harness (#53) runs about 2,100 query cases through two or more server groups and through the plain
engine over one store holding the same data, across disjoint, overlapping, migration-seam and native histogram
setups and every dedup mode. It runs in the regular test job. Its known divergences are the open findings from the
review, all in query pushdown or gap filling.
