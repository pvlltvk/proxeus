**Per-query backend stats: what each backend was asked and what it cost, in the API and under every query panel.**
Also a config rename: `cross_group_exact_aggregates` is now `cross_group_exact`.

## Per-query backend stats

With the `stats` parameter set (as for Prometheus), `/api/v1/query` and `/api/v1/query_range` add a `backends`
section to `data.stats` (#66):

- per `server_group`: requests, errors, series, samples and the summed request time;
- the requests themselves: group, `pushdown` or `raw`, the query or selector as handed to the group (before
  per-target rewrites such as `inject_matchers`), time range, duration, series, samples and status.

The list keeps the first 100 requests; `requestsTruncated` counts the rest, which still count towards the group
totals. A failure hidden by `ignore_error` or `downgrade_error` still shows. Prometheus' own stats are unchanged, and
without `stats` nothing is recorded.

```sh
curl -s 'http://localhost:8082/api/v1/query' --data-urlencode 'query=sum(up)' -d stats=true | jq .data.stats.backends
```

The query page shows the same data under each panel, in Table and Graph view. Each panel shows the stats of its own
latest result (#67); a panel whose query failed, or whose result can't be identified for sure, shows no block rather
than old numbers (#67, #68).

## Breaking: `cross_group_exact`

`cross_group_exact_aggregates` is renamed `cross_group_exact` (#65): it makes the whole query exact, not just
aggregations. The fallback reason in `proxeus_pushdown_nodes_total` changes from `exact_aggregates` to `exact`. The old
key is ignored, so a config that still uses it runs with exact mode off.

- A target that hasn't been probed yet shows `-` as its last probe time (#69).
