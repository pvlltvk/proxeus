## Cardinality

`/proxeus/api/cardinality.json` asks every `server_group` for its `/api/v1/status/tsdb` in parallel (the first target
that answers) and returns one entry per group (#72):

- total series and label=value pairs, top series by metric name, top label names by value count, top label=value
  pairs;
- what only one backend type reports: memory by label name for Prometheus/Thanos, series by label name and by
  focus-label value for VictoriaMetrics;
- `coverage`: what the numbers cover. Prometheus and Thanos report their head block (`head`, with its time range),
  VictoriaMetrics one day's index (`day`, today in UTC unless `date` is set).

Groups are never summed: series kept by more than one group would count twice. `topN` (default 10, at most 1000)
applies to every group; `match[]`, `focusLabel` and `date` are sent to `backend_type: victoriametrics` groups only and
listed under `notApplied` for the others. A group that fails or takes longer than 10 s carries an `error`; the rest
still answer.

```sh
curl -s 'http://localhost:8082/proxeus/api/cardinality.json?topN=5&focusLabel=job' | jq '.groups[] | {name, totalSeries, notApplied}'
```

The Cardinality page (Server status menu) shows the same data, with Top N, series filter, focus label and date
fields. It replaces the TSDB status page: `/tsdb-status` redirects to `/cardinality`.

For a Thanos group, the numbers are what Thanos Query reports: the head stats of every receiver, sidecar and ruler
added up. Replicated series count once per replica, and blocks already in object storage are not included.

## Breaking: `/api/v1/status/tsdb`

`/api/v1/status/tsdb` answers 501 and names the cardinality endpoint (#72). It used to answer empty stats, which
looked like a backend with no series.
