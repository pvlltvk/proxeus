**Query pushdown and gap filling now match a single complete store.** This release closes the remaining findings from
the code review behind v0.5.1.

## Correctness

- **Aggregate against a number** (#55). `max(foo) < 5`, `topk(1, foo) * -1` and similar were sent whole to every
  backend, and the aggregation was re-run over results each backend had already filtered or transformed. With `foo`=1
  in one backend and 10 in another, `max(foo) < 5` returned 1 instead of nothing. Now only the aggregation is pushed
  down, and proxeus applies the comparison or arithmetic itself.
- **`scalar()` and `vector()`** (#55). Both depend on how many series the whole input has, but each backend evaluated
  them alone: `vector(scalar(foo))` with one `foo` series per backend returned a value instead of NaN. Functions are
  now pushed down only from an explicit list of functions that work series by series; `scalar`, `vector`,
  `sort_by_label` and functions added in future versions are evaluated by proxeus over the pushed-down argument.
- **`offset` with time-dependent functions** (#55). Proxeus removed selector offsets and moved the request time
  instead, which is equivalent unless the expression also reads the evaluation time. `predict_linear(foo[5m] offset
  1m, 60)` predicted from the wrong moment and `clamp_min(foo offset 1m, time())` clamped against the wrong time, even
  with a single backend. Such subtrees now keep the offset in the query sent to the backend.
- **Gap filling with floats and histograms** (#57). Gaps were filled separately for a series' float and histogram
  samples, so a winner's float did not stop a loser's histogram from landing at the same timestamp: a gapless float
  winner with a histogram copy elsewhere came back as both, two samples per timestamp. Each series is now filled on
  one timeline holding both sample types.

## Exact mode

With `cross_group_exact_aggregates: true` and more than one `server_group`, proxeus now pushes nothing down and
evaluates every query over the deduplicated, gap-filled raw series (#55). Before, only aggregations were evaluated
locally, so `rate()` and other functions still ran inside each backend. That was wrong whenever a series' history is
split across backends: at a migration cutover, `sum(rate(foo[5m]))` returned half the true rate.

The mode is now correct across overlap and migration seams, and costs more. Raw samples replace one value per step, so
a query fetches roughly step ÷ scrape interval times more data than before: no change for short ranges, ×8 for a 24h
dashboard at a 2m step over 15s data, ×40 for 7 days at a 10m step. Wide ranges over many series can exceed
`--query.max-samples`. It fits a migration window better than permanent use; the README covers the trade-off.

Without exact mode, a series split across backends is still evaluated separately in each, now documented in the
README.

## Documentation

- **Known overlap** (#56). When you know which endpoints two backends both hold, exclude them from all but one group
  with `inject_matchers`. The groups are then disjoint, so aggregations stay exact and pushed down without exact mode.
- **Joins across groups** (#56). Every series carries its group's `labels`, so `foo + bar` between series from
  different groups is empty and `foo or bar` keeps both. Use `ignoring(<group label>)` or `on(...)`.

## Tests

The differential harness gained per-group `inject_matchers` and scenarios for one large backend next to smaller,
mostly disjoint ones with partial overlap (#56). Its known divergences went from 236 cases to 30, all documented
limitations: per-backend evaluation at a seam outside exact mode, and joins across groups.
