**proxeus is now read-only, and cross-group dedup fills gaps by default.** Rule evaluation, alerting and
`remote_write` are gone, along with about 1,800 lines that supported them. Backend latency is a histogram, so p99 is
finally visible, and three metrics that tracked query volume rather than anything actionable are removed.

## Gap filling on by default

`cross_group_dedup_fill_gaps` now defaults to `true` (#46). With `cross_group_dedup` on, a hole in the winning group's
series is filled from the other groups in priority order; the winner's own samples are never replaced. Set it to
`false` to return the winner whole. It no longer requires `cross_group_dedup` to be set explicitly, since it has no
effect without it.

The default follows a 4-hour soak in the sandbox: two instances on the same Thanos and VictoriaMetrics backends,
identical except for this option, 9,870 query pairs over 1h/6h/24h ranges with an 8-minute outage on each backend.
Filling lost no points, changed no values, and filled nothing outside the outages. p99 latency went from 238 to
272 ms, allocation from 7.2 to 8.9 MiB/s, RSS was unchanged.

## Read-only

Removed (#47):

- In-process rule evaluation (`rule_files`), the Alertmanager notifier (`alerting`) and alert-state backfill, with the
  `--rules.*` and `--alertmanager.notification-queue-capacity` flags.
- `remote_write` and its write-ahead log.
- The `remote_write_exporter` binary, from the release assets and the image.

A config containing `rule_files`, `alerting` or `remote_write` is now rejected at load and by `--check-config`. Run
rules in a ruler that queries proxeus instead: Thanos Ruler (`--query=http://proxeus:8082`), vmalert
(`-datasource.url`), or a rules-only Prometheus with `remote_read` against proxeus. Their rules still span every
backend, because their queries go through proxeus.

`/api/v1/rules`, `/api/v1/alerts` and `/api/v1/alertmanagers` keep answering, with empty lists, so Grafana's rule
listing works.

`--storage.path` now only holds the active query tracker for `--query.max-concurrency`. The deprecated
`--storage.tsdb.path` alias is removed (#48).

## Metrics

- **`proxeus_server_group_request_duration_seconds` is a histogram** instead of a summary without quantiles (#46). It
  exposes classic buckets (10 ms to 120 s) and native histogram buckets; `_sum` and `_count` are unchanged. The bundled
  Grafana dashboard's "Backend latency" panel now shows p50 and p99 per server group.
- **Removed:** `proxeus_cross_group_dedup_filled_samples_total` (it re-counted the same historical gaps on every
  query), `proxeus_cross_group_dedup_metadata_collisions_total` (grew with `/api/v1/series` traffic; the main
  collisions counter already shows whether dedup matches), and `process_reload_time_seconds` (a duplicate of
  `prometheus_config_last_reload_success_timestamp_seconds`).
- Typos fixed in the label-filter metrics' help text.

## Helm chart

Chart version **0.3.1 → 0.4.0**, `appVersion` **v0.4.0 → v0.5.0**. `rules.alertingOnly` and `storage.persistence`
(with its PersistentVolumeClaim) are removed; `storage.path` stays on an `emptyDir`. The default config no longer
carries a `remote_write` block.
