**Fixes from a second code review: pushdown of nested global functions, backend credentials sent across redirects,
and stale markers in gap filling.** Proxeus also stops answering `/api/v1/read`, which never worked.

## Correctness

- **Nested global functions** (#61). Only the outermost function of a pushed-down subtree was checked against the
  list of functions that work series by series; an aggregation or allowed function sent everything below it to each
  backend. `scalar`, `vector`, `absent` and the like inside it were then evaluated per backend: with one `foo` series
  in each of two backends, `sum(vector(scalar(foo)))` returned the sum of both values instead of NaN, and
  `sum(absent(meta))` returned 1 when another backend has `meta`. Every function in the subtree is now checked;
  `label_replace` and `label_join` still go down with the aggregation around them.
- **Empty truncated window** (#62). With `truncate`, aligning the start to the step grid could move it past the
  clamped end, and the backend rejected the request. Such a window has no evaluation step, so it now returns empty
  without a backend call.
- **Gap filling and stale markers** (#63). Both apply where stale markers reach proxeus (`remote_read` groups). A
  lower-priority group's stale marker was dropped when its samples filled a gap, so its last value carried through
  the lookback window after it stopped; it is now kept. A native histogram stale marker was treated as a sample and
  didn't open a gap the way a float marker does.

## Security

- **Redirects to another host** (#62). With `follow_redirects` on (the default), redirects were followed through the
  group's transport, which adds forwarded headers, `http_headers` and the Authorization header on every request.
  A backend redirecting elsewhere had those credentials sent to the new host. Proxeus now refuses redirects to a
  different scheme or host, for queries, `remote_read` and the UI's backend probes; same-host redirects still work.

## Remote read

Proxeus no longer serves `/api/v1/read` and answers 501 (#59). The endpoint came with the embedded Prometheus API but
never worked: Prometheus' remote-read client asks for streamed chunks, which proxeus can't produce (HTTP 500), and a
sample-format request without hints returned series with no samples. The README recipe for a rules-only Prometheus
reading through proxeus is gone; Thanos Ruler and vmalert query proxeus over the HTTP API. Proxeus reading from
backends with `remote_read: true` is unchanged.

## Documentation

- Exact mode over the HTTP API: raw samples fetched without `remote_read` carry no stale markers, so a series that
  disappeared can answer instant queries for up to the lookback delta (#59).
- Classic histograms: `histogram_quantile` and `histogram_fraction` are pushed down per group, so a histogram's
  `_bucket` series must stay in one group (#59).
- `limit_ratio` picks series by a hash of their labels, which include the group label, so its subset differs from a
  single store's.
